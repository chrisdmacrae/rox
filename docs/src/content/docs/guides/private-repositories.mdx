Manage Git SSH key paths on the launcher:

```sh
rox key add ~/.ssh/project_readonly
rox key remove ~/.ssh/project_readonly
```

These commands update `git_keys` in `${XDG_CONFIG_HOME:-$HOME/.config}/rox/config.json`. Removing a path doesn't delete the key file. Pass `--config PATH` to `rox key` and `rox up` to use a different config file.

## How keys are used

Rox loads only the selected keys into an SSH agent on the launcher, one per guest, and forwards that agent into the guest. **Private keys never leave the host.** The guest can ask the agent to sign, but it can't read the keys.

- **While cloning**, a temporary agent is forwarded to `git clone` alone. The setup hook never gets it.
- **For the guest's whole life**, after the setup hook, Rox keeps the guest's own agent forwarded to `~/.rox/NAME/git-agent.sock` in the guest. The guest's Rex server and `rox shell` set `SSH_AUTH_SOCK` to it, so `git fetch`, `git pull` and `git push` work in every terminal, for you and for agents. The clone also adds the pinned Git server keys to the guest's `~/.ssh/known_hosts`, so later fetches trust the same servers.

The rox service restarts the agent and its forward after the guest or the launcher restarts. An encrypted key needs its passphrase again after the launcher restarts, so run `rox reconnect NAME` in a terminal. `rox stop` and `rox down` stop both.

Anything running in the guest can use the keys while the forward runs, including for repositories other than the project's. Prefer read-only deploy keys, or keys that reach only what the guest needs. Pass `--no-git-agent` to `rox up` to give one guest keys only while it clones, or set `"git_agent": false` in the config to do that for every guest.


- `git_keys` is a list of SSH private key paths on the launcher. Prefer read-only deploy keys. Without `git_keys`, Rox uses your default SSH keys in `~/.ssh` (`id_ed25519`, `id_ecdsa`, `id_rsa` and their security-key variants), the ones `git clone` would use. Set `"git_keys": []` to clone with no key. Repeat `--git-key PATH` to use a different list for one launch. Encrypted keys can prompt for their passphrase on the host.
- `git_known_hosts`, or `--git-known-hosts PATH`, supplies verified host keys for your Git servers. If you leave it out, Rox copies the matching host and port entries from the launcher's `~/.ssh/known_hosts`. The guest still verifies the server's key.

## Choosing the repository and branch

Rox uses the current branch's upstream remote and branch when one is configured. Otherwise it uses `origin` and the current branch name.

- `--remote NAME` picks a different remote.
- `--repo URL` sets the clone URL directly.
- `--branch NAME` picks an existing remote branch.

For an HTTPS remote that needs authentication, use its SSH clone URL instead:

```sh
rox up container \
  --repo git@github.com:organization/project.git \
  --git-key ~/.ssh/project_readonly
```

<Aside>
	Rox accepts only SSH and HTTPS remotes. HTTPS URLs can't include credentials.
</Aside>
