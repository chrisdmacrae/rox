On an Apple Silicon Mac, install [Tart](https://tart.run) and prepare one template for each guest OS.

## Prepare a macOS template

Install the Rex app on the Mac that runs the guests, then let rox build the template:

```sh
rox template macos                 # on this Mac
rox template macos --host mini     # on a Rex remote host
```

It pulls `ghcr.io/cirruslabs/macos-tahoe-base:latest` into `rox-macos` (about 30 GB the first time), authorizes a VM login key, pins the host key, replaces the default `admin` password, installs Rex, checks that the template boots to SSH and to its desktop, shuts it down and fills in the `macos` [config](../../reference/configuration/). The new password is saved next to the config as `rox-macos-admin-password`. Run the same command after you upgrade Rex. See [`rox template`](../../reference/cli/#rox-template-macos--rox-template-linux) for the options.

<Aside type="caution">
	macOS signs the template in at boot with the password stored in `/etc/kcpassword`. If you change the template's password by hand, update that file too, or the template boots to the login window and GUI work in its guests fails.
</Aside>

## Prepare Linux templates

```sh
rox template linux                    # rox-ubuntu, from Ubuntu 24.04
rox template linux --distro debian    # rox-debian, from Debian trixie
rox template linux --distro fedora    # rox-fedora, from Fedora 42
rox template linux --distro arch --base ghcr.io/you/arch-tart:latest
```

Each one gets Git and Rex, a new password, lingering for the guest account, key-only SSH and the host key all Linux templates share. Rox checks that a clone boots and takes SSH. The first template becomes `linux.image`. Launch the others with `rox up linux --image rox-debian`, or make one the default with `--default`. Cirrus Labs publishes no Arch image, so build or find a Tart Arch image and pass it with `--base`. Rox detects pacman, zypper and apk as well as apt and dnf. See [`rox template`](../../reference/cli/#rox-template-macos--rox-template-linux) for the options.

## Prepare a template by hand

For an image rox template can't prepare, clone it and set it up from its console.

```sh
tart clone ghcr.io/cirruslabs/ubuntu:24.04 rox-ubuntu
tart clone ghcr.io/cirruslabs/macos-tahoe-base:latest rox-macos
```

Boot each template once with `tart run TEMPLATE`.

<Steps>

1. **Enable SSH.** On macOS, turn on **System Settings → General → Sharing → Remote Login**. On Ubuntu, install `openssh-server` and run `sudo systemctl enable --now ssh`. Use key-based login, and change the image's default password before you use the template. SSH must allow local Unix-socket forwarding. For private Git clones, it must also allow SSH agent forwarding.

2. **Create a VM login key on the host.**

   ```sh
   ssh-keygen -t ed25519 -f ~/.ssh/rox_vm
   ```

   Add the public key to the guest user's `~/.ssh/authorized_keys`. Set `~/.ssh` to `700` and the file to `600`. Keep the private key on the host and set `identity` to its path. If the key has a passphrase, load it into your regular SSH agent before you launch.

3. **Install Git, Bash, and Rex in the guest**, then check `rex version` as the SSH user. On Ubuntu, use the official Rex Linux installer. On macOS, install the official Rex app. If the CLI isn't on SSH's PATH, link its bundled executable into `~/.local/bin`:

   ```sh
   mkdir -p ~/.local/bin
   ln -s '/Applications/Rex.app/Contents/Helpers/Rex Server.rex/Contents/MacOS/rex' ~/.local/bin/rex
   ~/.local/bin/rex version
   ```

   On Ubuntu, enable lingering for the guest account with `sudo loginctl enable-linger "$USER"`. See [Rex installation](https://www.superlogical.com/rex/docs/installation) and [Rex over SSH](https://www.superlogical.com/rex/docs/linux/remote-access).

4. **Pin the host key.** From the guest console, read its SSH host public key, usually `/etc/ssh/ssh_host_ed25519_key.pub`. Save it to a file on the host and set `host_key` to that path. Keep the host key the same across clones.

5. **Configure and shut down.** Set `image` and `user` for the template in the [config](../../reference/configuration/). Check that it boots to SSH without any manual steps, then shut the template down before launching clones.

</Steps>

## Launch

```sh
rox up linux
rox up macos
```

Each launch clones the template into a new VM. If the project has a `.rox.sh`, the first launch also builds a `rox-REPO-BACKEND` [project image](../project-images/) from the template, and later launches clone that image instead.

<Aside>
	See [Tart's quick start](https://tart.run/quick-start/) for more on preparing templates and SSH.
</Aside>
