Install rox on the machine that runs the guests. That machine is called the **launcher**. Your agent runner goes inside the guests, not on the launcher.

## Requirements

- Python 3.9 or later
- Git
- OpenSSH 8.2 or later
- [Rex](https://www.superlogical.com/rex/docs/installation)
- For containers on an Apple Silicon Mac, Apple's [container](https://github.com/apple/container) tool with its services running (`container system start`). Rox uses it by default there, because it gives every container its own lightweight VM instead of sharing one Linux VM.
- For containers on Linux or Windows hosts, or on a Mac if you choose it, a running Docker or Podman engine.
- For VMs, [Tart](https://tart.run) on an Apple Silicon Mac. See [Tart VMs](../../guides/tart-vms/).

## Install the CLI

<Steps>

1. Download the latest release into `~/.local/share/rox` and link `rox` into `~/.local/bin`.

   ```sh
   curl -fsSL https://github.com/chrisdmacrae/rox/releases/latest/download/rox.tar.gz -o /tmp/rox.tar.gz \
     && rm -rf ~/.local/share/rox && mkdir -p ~/.local/share/rox ~/.local/bin \
     && tar -xzf /tmp/rox.tar.gz -C ~/.local/share/rox --strip-components=1 \
     && ln -sf ~/.local/share/rox/rox ~/.local/bin/rox && rm /tmp/rox.tar.gz
   ```

2. Make sure `~/.local/bin` is on your `PATH`.

3. Check that it runs.

   ```sh
   rox --help
   ```

4. Optionally, install the [rox skill](../../guides/agents/) for Claude Code or Codex.

   ```sh
   rox skill install
   ```

</Steps>

Rox finds its guest scripts and Containerfile next to the real file in `~/.local/share/rox`, which is why the command links `rox` instead of copying it.

### Upgrade or pin a version

A release install keeps itself up to date: before a command, at most every six hours, rox asks GitHub for the latest release. When one is out, it downloads it, checks it against the release's `rox.tar.gz.sha256`, swaps it in, updates the rox skill for each agent that has it, and runs your command with the new version. If it can't write to its install folder, or it's a Git checkout, it says the release is out instead. Run `rox self-update` to update now, or `rox self-update --check` to only check. Set `"updates": "notify"` in the rox config to be told without installing, or `"off"` to stop checking. `ROX_UPDATES` overrides it for one command. You can also run the install command again to upgrade, then `rox skill install` to update the skill. The installed version is in `~/.local/share/rox/VERSION`. To install a specific version, replace `latest/download` with `download/vX.Y.Z`. See [releases](https://github.com/chrisdmacrae/rox/releases) for the available versions.

Each release also includes `rox.tar.gz.sha256`. To check a download, keep the archive and run `shasum -a 256 -c rox.tar.gz.sha256` in the folder that holds both files.

## The base container image

You don't need to build anything. The first `rox up container` builds the `rox:linux` image with your container engine, which takes a few minutes, and later launches reuse it. When a new rox release changes the image, Rox rebuilds it on the next launch.

On an Apple Silicon Mac, Rox uses Apple's container tool. Elsewhere it uses Docker. To choose an engine, set `"engine"` to `container`, `docker`, or `podman` under `container` in the [config](../../reference/configuration/), or pass `--engine` when you launch.

Apple's container gives each container 1 GB of memory by default. For heavier agents, set `"memory": "4G"` under `container` in the config, or pass `--memory` at launch.

With Apple's container, guests can run Docker, so `docker compose up` works for dependencies such as Postgres. The `rox:linux` image ships Docker Engine and the Compose plugin, and the workspace user is in the `docker` group. Each Apple container is its own VM, so Rox gives it every Linux capability and starts Docker inside it. Neither reaches your Mac. Published ports open on the guest's `localhost`. Docker and Podman containers share the host's kernel, so Rox doesn't start Docker in them. Docker isn't running while a project image builds, so start Compose services from [`.rox.sh`](../../guides/setup-hook/) only when `ROX_PHASE` is `boot`, or from a Rex terminal.

For project dependencies, use a [setup hook](../../guides/setup-hook/) rather than changing the base image.

<Aside>
	Rex.app builds that keep their own host list don't pick up `rex hosts add`. To add a guest to the Rex app on this machine, run `rox add-remote-host NAME`. It copies the guest's address, its tailnet name when it has one, and opens **Add Remote Host** so you can paste it. It works for guests on other Rex hosts too, when they're on the tailnet.
</Aside>
